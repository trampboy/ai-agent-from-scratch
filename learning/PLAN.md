# 小模型训练学习计划

确认日期：2026-10-05。当前阶段：P0 基础检查，等待完成第一份练习。

本计划用于学习模型训练全过程，并逐步把自己训练的小模型接入当前 Agent。主线是自己实现微型 GPT、从随机权重预训练、监督微调和工具调用；完成后，再使用已有的 Qwen 权重做对照实验。GAIA 是后续应用与评测目标，不承诺教学模型能够全面替代当前 DeepSeek 服务。

## 已确认的条件

- 目的：掌握基本训练技能，理解代码、数据和实验结果。
- 硬件：本机会话读取为 Apple M5、32GB 统一内存；尚未进行训练速度与内存实测。
- 成本：优先本机。先用小样本测通流程，遇到明确瓶颈后再估算云训练成本。
- 教材：《从零构建大模型》为主线，《动手构建大模型》用于补充微调和部署知识。当前仅提供封面，尚未读取书籍正文。
- 项目基础：已有 my_agent 教学实现；保持 scratch_agents 参考实现不变。
- 当前环境已发现 uv、Python 3.13.7 和项目 .venv；尚未验证 PyTorch、MPS 或 MLX 的安装与可用性。

## 协作方式

每次只推进一个可验收的小任务：先说明目标和必要概念，由学习者动手实现或回答，再一起检查结果、定位错误并记录进度。优先给提示和解释；需要完整示例时再提供，避免直接代写整个学习项目。

完成任务必须有证据，例如代码、运行输出、实验记录或能独立解释的答案。阅读资料或运行成功本身不代表理解。每次验收后更新本文件的状态、问题与下一步。

后续从本文件恢复进度；不设置自动提醒或后台训练。训练代码使用独立目录与环境，具体依赖在开始代码练习时确认，避免影响当前 Agent 环境。默认不提交 Git、不下载大模型、不启动付费服务。

## P0 理解一次参数更新

状态：进行中，尚未验收。

任务：完成 [第一次梯度练习](exercises/00-gradient.md)，区分前向计算、损失、梯度、反向传播和优化器更新。能解释则直接进入 PyTorch；不熟则学习 micrograd 的标量计算图和链式法则。

验收：

- [ ] 能手算一次参数更新，并解释参数增减的方向。
- [ ] 能说明反向传播和优化器分别做什么。
- [ ] 能解释为什么多个训练步之间通常需要清除梯度。
- [ ] 用一个小例子将手算结果与自动求导结果比较。

参考：《从零构建大模型》附录 A；Karpathy 的 micrograd 教学。

## P1 实现微型 GPT

状态：未开始。

任务：按主教材第 2–4 章，逐步实现文本编码、训练样本、embedding、因果自注意力、Transformer 模块和输出层。先选择便于本机调试的结构，参数规模在实现时根据词表等配置计算，避免先追求大模型。

验收：

- [ ] 能解释输入 token、目标 token 的错位关系及各层张量形状。
- [ ] 因果遮罩能阻止当前位置读取后面的 token。
- [ ] 能执行前向计算和生成，并解释随机权重模型的输出局限。
- [ ] 能统计参数量并说明主要参数来自哪些层。

## P2 从随机权重预训练

状态：未开始。

任务：按主教材第 5 章，使用来源明确、适合学习实验的少量文本训练 P1 模型。按源文档先划分训练与验证数据，再切分样本，避免重叠文本泄漏。先跑几十步测内存与速度，再决定规模。

验收：

- [ ] 实现训练、验证、保存和恢复；checkpoint 包含模型、优化器及训练进度等必要状态。
- [ ] 记录训练与验证 loss、token 数、训练时间、设备和配置。
- [ ] 比较固定提示词下的训练前后输出，能解释过拟合和验证 loss 的作用。
- [ ] 能独立修改学习率或上下文长度，并解释实验结果。

产出：自己的基础模型 checkpoint。规模小和训练少会限制能力，loss 下降不代表已经具备问答或 GAIA 能力。

## P3 对自己的模型做监督微调

状态：未开始。

任务：从 P2 的 checkpoint 继续训练，使用简单问答和格式化输出数据。学习监督微调 SFT、对话模板和 loss mask。先用可理解的全参数微调走通流程，再按主教材附录 E 学习 LoRA 并对比。

验收：

- [ ] 明确本阶段从自己的预训练权重加载，而非重新随机初始化或加载 Qwen。
- [ ] 能解释哪些 token 参与 loss，以及原因。
- [ ] 同一题的改写归入同一数据分组，保留未见过的评测样本。
- [ ] 比较微调前后表现，区分格式正确与内容正确。
- [ ] 能说明全参数微调、LoRA、量化的区别。

若基础能力不足，先缩小任务范围并分析数据与预训练问题，不因微调效果差就直接进入强化学习。

## P4 让自己的模型调用工具

状态：未开始。

任务：先训练单次计算器调用，再训练接收真实工具结果后回答。逐步扩展至文件或表格任务、多步调用、无需工具的任务与错误恢复。起步用少量人工核验样本跑通，再视结果扩充。

训练轨迹包含用户问题、assistant 工具调用、实际 tool 返回和最终回答。工具由程序执行，模型生成调用指令。若使用教师模型辅助生成，必须核验执行结果；不把教师生成的虚构工具结果当作真实证据。

验收：

- [ ] 工具名称和参数可以被程序解析并执行。
- [ ] 对未见数字和表达方式进行评测，报告有效调用率与最终答案正确率。
- [ ] 加入工具错误样本，检查是否能修正参数或合理停止。
- [ ] 接入 my_agent，验证完整运行链路。

## P5 使用 Qwen 做对照实验

状态：未开始，属于主线完成后的对照实验。

任务：分别加载现成 Qwen 权重并在同类任务上评测与微调。此前讨论的候选是 Qwen3-0.6B 与 Qwen3-4B-Instruct-2507，实施前重新核实工具链兼容性。二者是分别训练的模型，不是把 0.6B 扩展为 4B。

Mac 实践候选为 MLX-LM 的 LoRA 或 QLoRA；具体配置由小规模内存实测决定。与自己的模型比较时，保持任务、数据划分、工具和评测规则一致，并注明参数量和既有预训练资源不同，不能将结果差异只归因于微调方法。

验收：

- [ ] 比较自己模型、未微调 Qwen、微调 Qwen 和当前 DeepSeek 基线。
- [ ] 记录成功率、调用格式错误、循环或超步数、耗时和实际费用。
- [ ] 用错误案例解释基础模型能力和任务微调各自的作用。
